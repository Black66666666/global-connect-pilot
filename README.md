# Global Connect — Plugin v0.3.1

Global Connect превращает реальный человеческий запрос в переносимую карточку и измеряет, какой маршрут через людей, сообщества и подключённые сервисы дал полезный результат.

## Что уже работает

Пилот работает на Cloudflare Workers + D1.

- публичные карточки запросов без обязательной регистрации;
- русский и английский интерфейс для карточек, созданных через MCP;
- исходная публичная ссылка запроса при наличии;
- действия получателя: `могу помочь`, `знаю куда копать`, `знаю человека`, `нужно уточнение`, `не могу помочь`;
- отдельный `ref` для каждого маршрута;
- учёт факта отправки, открытия, ответа и типа ответа;
- журнал маршрутов без хранения адресов получателей в D1;
- публичная агрегированная статистика без текста ответов и контактов;
- отдельный операторский доступ к списку запросов и журналу маршрутов;
- MCP endpoint `/mcp`;
- пакет плагина: `plugin.json`, `mcp.json`, `skills/global-connect/SKILL.md`;
- публичные страницы `/plugin`, `/privacy`, `/terms`, `/support`;
- endpoint проверки домена `/.well-known/openai-apps-challenge` через секрет `OPENAI_APPS_CHALLENGE`;
- автоматическая проверка сборки Cloudflare Worker в GitHub Actions.

## Публичные MCP-инструменты

Без учётной записи доступны только операции, которые не раскрывают внутренний индекс или журнал маршрутов:

- `draft_request` — подготовить карточку без сохранения;
- `create_request` — создать публичную карточку и получить ссылку;
- `get_request` — получить карточку по уже известному ID;
- `get_request_stats` — получить только агрегированные результаты известной карточки.

`create_request` ничего не рассылает и не публикует во внешних сообществах. Он только создаёт публичную карточку. Анонимное создание ограничено глобальным часовым лимитом для защиты пилота от спама.

## Операторские MCP-инструменты

При подключении MCP с действующим `GC_ADMIN_TOKEN` дополнительно появляются:

- `list_requests` — список запросов;
- `list_routes` — внутренний журнал маршрутов конкретного запроса;
- `register_route` — зарегистрировать планируемый или уже выполненный маршрут и получить отслеживаемую ссылку.

Приватный операторский URL:

`https://global-connect-pilot.biv-ai-lab.workers.dev/mcp?key=<GC_ADMIN_TOKEN>`

Административный ключ не хранится в репозитории и не должен передаваться в переписке.

## Измерение маршрута

Перед распространением оператор регистрирует отдельный маршрут. Например:

`reddit_berlin_01`

или

`discord_music_02`

Инструмент возвращает ссылку:

`https://global-connect-pilot.biv-ai-lab.workers.dev/r/<id>?ref=<source_ref>`

После этого Global Connect различает:

`маршрут зарегистрирован → отправлен → карточка открыта → получен ответ → тип ответа`

Это позволяет корректно учитывать и нулевой результат: например, `отправлено 6, открыто 0`, а не видеть только тех, кто уже кликнул.

## Реальный пилот Berlin 70s

Карточка `berlin70s1` создана на основе реального запроса с явным согласием автора на дополнительное распространение.

Для неё зафиксированы шесть целевых email-маршрутов через музыкальные сообщества и людей в Берлине. В журнале маршрутов хранятся обезличенный `ref`, канал, понятная метка адресата и время отправки — не email-адрес получателя.

## Развёртывание

Cloudflare подключён к репозиторию `Black66666666/global-connect-pilot`.

Команда:

`npm run deploy`

Скрипт находит существующую D1 `global-connect-pilot-db`, создаёт временный конфиг с UUID и выполняет `wrangler deploy`.

Проверка сборки без публикации:

`npm run check:build`

Проверка публичного MCP:

`npm run smoke:mcp`

Создание тестовой публичной карточки намеренно выключено по умолчанию. Для явной проверки записи:

`MCP_TEST_PUBLIC_CREATE=1 npm run smoke:mcp`

## Архитектура

Текущий контур:

`ChatGPT / Codex → Global Connect Plugin → MCP → Cloudflare Worker → D1 → публичная карточка`

Операторский контур маршрутизации:

`Global Connect → register_route → отслеживаемая ссылка → внешний канал → открытие / ответ → статистика`

Следующий слой продукта:

`Global Connect → Social Relay → AgentMail / Reddit / Discord / Telegram`

Для каналов, которые работают от имени личного аккаунта пользователя, потребуется штатная авторизация соответствующей площадки. Отправка или публикация наружу должна быть отдельным явно описанным инструментом, а не скрытым побочным эффектом создания карточки.
