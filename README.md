# Global Connect — пилот 0.8

Экспериментальная карточка запроса для проверки одной гипотезы: может ли короткая человеческая подсказка открыть путь, которого не нашёл цифровой поиск.

## Почему Cloudflare

Пилот рассчитан на Cloudflare Workers + D1:

- публичный HTTPS без собственного сервера;
- приложение не зависит от домашнего мини-сервера;
- D1 хранит запросы и ответы;
- бесплатного уровня достаточно для небольшого пилота;
- Python Workers поддерживает FastAPI.

## Развёртывание через GitHub

1. В Cloudflare открыть `Workers & Pages` → `Create application` → `Import a repository`.
2. Подключить репозиторий `Black66666666/global-connect-pilot`.
3. Имя Worker должно быть `global-connect-pilot`.
4. Cloudflare автоматически создаст D1 для binding `DB`, потому что в `wrangler.jsonc` ресурс указан без ID.
5. После первого развёртывания добавить секрет `GC_ADMIN_TOKEN` в Settings → Variables and Secrets.
6. Открыть `/health` и убедиться, что возвращается `{"ok":true}`.
7. Открыть `/?token=<GC_ADMIN_TOKEN>` для создания первого запроса.

Каждый push в `main` после подключения GitHub автоматически запускает новое развёртывание.

## Ссылки для рассылки

Для каждого адресата используется та же карточка с обезличенной меткой:

`https://<адрес>/r/<id>?ref=R001`

В базе хранится только `R001`, а соответствие `R001 → email` остаётся в таблице рассылки и не попадает в приложение.

Это позволяет посчитать:

- сколько адресатов открыли карточку;
- сколько ответили;
- какой тип помощи выбрали;

без хранения адресов получателей в публичном пилоте.

## Административная часть

- `/?token=...` — создать запрос;
- `/admin?token=...` — статистика;
- `/api/r/<id>` — машинное представление карточки.

`GC_ADMIN_TOKEN` не хранится в репозитории.
