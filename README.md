# Global Connect — Plugin v0.4.0

Global Connect превращает реальный человеческий запрос в переносимую карточку и измеряет, какой маршрут через людей, сообщества и подключённые сервисы дал полезный результат.

## Что уже работает

Пилот работает на Cloudflare Workers + D1.

- публичные карточки без обязательной регистрации;
- русский и английский интерфейс;
- сохранение публичного источника запроса;
- ответы `могу помочь`, `знаю куда копать`, `знаю человека`, `нужно уточнение`, `не могу помочь`;
- отдельный `ref` для каждого маршрута;
- учёт `отправлено → открыто → ответ получен → тип ответа`;
- публичная агрегированная статистика без частных текстов, контактов и целей маршрута;
- операторский журнал маршрутов;
- операторское чтение содержания ответов;
- отдельная фиксация реального исхода запроса: `pending / succeeded / failed / expired`;
- MCP endpoint `/mcp`;
- пакет плагина `plugin.json + mcp.json + skills/global-connect/SKILL.md`;
- публичные `/plugin`, `/privacy`, `/terms`, `/support`;
- подготовленный endpoint проверки домена `/.well-known/openai-apps-challenge`;
- CI: проверка структуры плагина, сборки Worker и живого MCP после развёртывания.

## Публичные MCP-инструменты

Без учётной записи доступны:

- `draft_request` — подготовить карточку без публикации;
- `create_request` — создать публичную карточку и получить ссылку;
- `get_request` — получить карточку по известному ID;
- `get_request_stats` — агрегированные показатели известной карточки и публичное состояние реального исхода.

Публичный MCP намеренно **не позволяет** перечислять все запросы, видеть внутренние маршруты, читать тексты ответов, контакты или частные заметки об исходе.

`create_request` создаёт только карточку. Он ничего не рассылает и не публикует наружу. Анонимное создание ограничено часовым лимитом против спама.

## Операторские MCP-инструменты

Приватный операторский MCP с действующим `GC_ADMIN_TOKEN` дополнительно даёт:

- `list_requests` — список запросов;
- `list_routes` — журнал маршрутов;
- `get_responses` — реальные ответы и подсказки; контакты возвращаются только по явному `include_contact=true`;
- `register_route` — зарегистрировать маршрут и получить отслеживаемую ссылку;
- `record_outcome` — зафиксировать фактический исход запроса и частную операторскую заметку.

Приватный URL:

`https://global-connect-pilot.biv-ai-lab.workers.dev/mcp?key=<GC_ADMIN_TOKEN>`

Ключ не хранится в репозитории и не должен передаваться в переписке.

## Измерение

Для каждого внешнего маршрута используется отдельная ссылка:

`https://global-connect-pilot.biv-ai-lab.workers.dev/r/<id>?ref=<source_ref>`

Внутри системы различаются:

`маршрут зарегистрирован → отправлен → карточка открыта → ответ получен → тип ответа → фактический исход`

Это позволяет видеть и нулевой результат: например `отправлено 6, открыто 0`, а не учитывать только тех, кто уже кликнул.

## Реальный пилот Berlin 70s

`berlin70s1` — реальный запрос с явным согласием автора на дополнительное распространение. Для него зарегистрированы шесть целевых email-маршрутов к людям и музыкальным сообществам Берлина. В D1 хранятся `ref`, канал, неперсональная метка цели и время отправки — не email-адрес получателя.

## Проверки

- `npm run check:plugin` — структура и обязательные данные пакета плагина;
- `npm run check:build` — Cloudflare dry-run сборка;
- `npm run smoke:mcp` — живой публичный MCP без создания тестовой карточки;
- `MCP_TEST_PUBLIC_CREATE=1 npm run smoke:mcp` — явная проверка создания и отрисовки карточки.

Один реальный тест публичной записи уже пройден: MCP создал карточку и её публичная HTML-страница успешно отрисовалась.

## Архитектура

Текущий контур:

`ChatGPT / Codex → Global Connect Plugin → MCP → Cloudflare Worker → D1 → карточка`

Операторский контур:

`register_route → отслеживаемая ссылка → внешний канал → открытие / ответ → get_responses → record_outcome`

Следующий слой:

`Global Connect → Social Relay → AgentMail / Reddit / Discord / Telegram`

Внешняя публикация должна оставаться отдельным явно описанным действием. Создание карточки не должно скрыто отправлять её кому-либо.

## Готовность к каталогу OpenAI

В репозитории уже есть:

- стабильный публичный HTTPS MCP;
- сайт, поддержка, privacy и terms;
- endpoint проверки домена;
- точные аннотации MCP-инструментов;
- 5 положительных и 3 отрицательных тест-кейса в `plugin.json`;
- release notes в `plugin.json`;
- сценарий демонстрационного видео.

До фактической подачи остаются организационные действия: подтверждение разработчика/организации в OpenAI Platform, получение challenge-token и установка его в `OPENAI_APPS_CHALLENGE`, запись и размещение демонстрационного видео, загрузка ZIP в портал и запуск tool scan/review.
